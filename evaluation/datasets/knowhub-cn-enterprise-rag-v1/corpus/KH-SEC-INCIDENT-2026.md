# 星舟科技信息安全事件响应预案

文档编号：KH-SEC-INCIDENT-2026  
版本：1.8  
生效日期：2026年1月15日  
责任部门：安全与合规部

## 1. 事件分级

### 1.1 P0 特别重大事件

满足任一条件即为P0：核心生产服务全面不可用；确认发生大规模敏感数据外泄；关键身份系统被完全控制；事件可能对公众或监管产生重大影响。

### 1.2 P1 重大事件

包括单个重要生产服务不可用、少量敏感数据疑似泄露、多个高权限账号被入侵，或者影响超过100名客户但尚未达到P0标准的事件。

### 1.3 P2 一般事件

包括影响范围有限的恶意软件、单个普通账号被盗、已被控制的小范围配置错误，以及未影响核心业务的数据完整性异常。

### 1.4 P3 低风险事件

包括被安全设备阻断的扫描、无实际影响的钓鱼邮件、单台测试设备异常和需要持续观察的弱信号。

## 2. 响应时限

| 等级 | 首次确认 | 管理层通报 | 目标遏制时间 |
| --- | ---: | ---: | ---: |
| P0 | 10分钟 | 30分钟 | 2小时 |
| P1 | 30分钟 | 2小时 | 8小时 |
| P2 | 4小时 | 1个工作日 | 2个工作日 |
| P3 | 1个工作日 | 按需 | 5个工作日 |

首次确认是指值班人员确认已经接手并开始判断，不代表事件已经解决。目标遏制时间用于控制影响扩散，不等同于永久修复完成时间。

## 3. 响应流程

安全事件按以下六个阶段处理：

1. 发现与登记：记录发现时间、报告人、受影响资产和初始证据；
2. 分析与定级：判断真实性、影响范围和事件等级；
3. 遏制：隔离账号、主机、网络或受影响功能，防止影响扩大；
4. 根除：移除恶意程序、泄露凭证和错误配置；
5. 恢复：验证系统完整性，分阶段恢复服务并加强监控；
6. 复盘与改进：识别根因、责任行动项和完成期限。

## 4. 角色职责

事件指挥官负责定级、资源协调和关键决策。技术处置负责人组织日志分析、遏制、根除和恢复。业务负责人评估客户与业务影响。法务与合规负责人判断监管、合同和个人信息通知义务。未经事件指挥官或授权发言人批准，任何人员不得对外发布事件信息。

## 5. 证据保护

处置人员应优先保存日志、时间线、受影响配置和必要的内存或磁盘证据。原始证据应只读保存并计算哈希。为了快速恢复而必须修改现场时，应记录修改人、时间、对象和理由。

## 6. 复盘要求

P0事件应在恢复后3个工作日内完成复盘会议，P1事件应在5个工作日内完成。复盘报告不得以追责个人为主要目的，应包含事实时间线、根因、有效措施、失效控制和明确负责人及期限的改进行动。

## 7. 与其他制度的关系

账号冻结与撤权按照《信息系统账号与访问控制规范》执行；业务系统恢复目标和备份选择按照《数据备份与恢复规范》执行。本预案规定响应组织和时限，不替代灾难恢复方案。
